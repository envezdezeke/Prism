## Design contract (read fully before writing code)

### A. Engine contract (do not change)
- `prism/engine/run.py` per tick calls, per live deal, `step_deal` then `sla_alerts`, and does `state.alerts.extend(due)`. Ticks happen only at file-arrival times and at the optional `end`, so one `step_deal` call must catch up everything between the previous call and `now`.
- `step_deal` mutates `stage`, `stage_entered_at`, `stage_log`, `human_requests`, `alerts` on the state in place. Because run.py also extends `state.alerts` with whatever `sla_alerts` returns, `step_deal` appends every alert itself and records each emitted key in the runtime. `sla_alerts` then returns only thresholds not yet emitted, marks them emitted and returns them, so after a `step_deal` call it returns an empty list and nothing duplicates. Standalone, it returns the crossed ladder alerts once.
- With empty rules (`rules.stages.pipeline` empty, which is what `load_rules(None)` gives and what the existing tiny-set tests use) every Move entry point is a safe no-op and `DealState.error` stays None. Move never raises `NotImplementedError`. Any other exception freezes that deal through the engine guard, so Move must not swallow its own bugs.
- Do not change `DealState` (its fields are pinned by a test). Per-deal Move memory is a `MoveRuntime` dataclass attached as the instance attribute `_move` (`runtime.get_runtime(state)`). Contract models (`HumanRequest`, `StageLogEntry`, `Alert`) are mutable pydantic models: update fields in place, append new ones, and build them with `format_sim_time` strings.
- `tests/test_engine.py` scans every `.py` in `prism/move` with an AST test: no `random`/`uuid`/`secrets` import, and no call to an attribute named now, utcnow, today, time, monotonic, perf_counter, time_ns or process_time. It also bans history-id literals and (when data/ exists) any sample folder name in any `prism/*.py`. Use `datetime.fromisoformat`, `timedelta`, `.weekday()`, `.date()`, `.replace()`.

### B. Data shapes Move reads (the gitignored pack; tests build synthetic copies with other names and run them through the real `load_stages`, `load_teams`, `load_assignments`)
- `stages.json`: `pipeline` list; `stages[S]` with `sla_hours`, optional `sla_hours_delegated`, `owner`, `required_to_exit` (list of text), `human_gate` null or `{type, who, options?}`; the committee-style stage has `routing: {delegated_max_amount (dollars), delegated_approver, full_committee_chair}`; `fraud_hold.who_decides` is prose that contains person ids; `stuck_deals` has `alert_at_pct_of_sla`, `escalate_at_pct_of_sla`, `second_escalation_at_pct_of_sla`, `second_escalation_to` (a person id).
- `teams.json`: people with `id`, `name`, `backup`, `escalates_to`, `notes`; an out-of-office window appears only as prose in `notes` ("OUT OF OFFICE YYYY-MM-DD HH:MM through YYYY-MM-DD HH:MM. Backup: ..."); `routing` maps stage names (and a fraud-hold key) to prose that contains person ids (a bare id, "id releases funds", "round-robin id1 / id2").
- `assignments.json`: folder to `{relationship_manager, credit_officer}`.
- `history/stage_events.csv` (optional, via `rules.history_dir`): columns include `stage`, `hours_in_stage`.

### C. Per-deal runtime and the two-pass catch-up (stage.py)
- Runtime fields (in `runtime.py`): `started`, `first_doc_at`, `owner`, `ready_at` (when the current stage became evaluable), `eval_pending`, `gate_sent{stage}`, `gate_satisfied{stage}`, `requested_issues` (set), `emitted` (set of dedupe keys such as "Stage:150" and "deadline_risk"), `alert_times{"Stage:pct"}`, `reqs` (list of `ReqMeta`: idx into `state.human_requests`, gate, stage, group, to, kind, at, due, recorded, processed, superseded), `decisions{gate: (person id, time)}`, `frozen_at`, `terminal` and `terminal_at`, `watermark` (latest event time processed; never go back), `view`, `credit_memo`, `resend_after`, `covering` note data.
- `View` = snapshot of what Read can change at a tick: open issues (sorted tuple), `last_arrival` (from `state.last_arrival_at`, else latest `Doc.arrive_at`), and the set of fact names with a value. Everything else (amount, product, needed_by, legal name, fraud) is read live.
- `step_deal(state, rules, now)`: no-op if the pipeline is empty. Pass 1 (only if a previous view exists): process every event with time strictly before `now` using the PREVIOUS view. Pass 2: set `eval_pending` if the view changed, then process every event with time at or before `now` using the CURRENT view. Save the current view. A one-shot call on a fresh runtime has no previous view, so pass 2 does everything with the current view. Calling `step_deal` twice at the same `now` changes nothing (every action is guarded by a runtime flag or emitted key). Hard cap of 10,000 events per call, then raise RuntimeError (engine guard freezes the deal).
- Event sources, earliest time first, ties broken by priority then stable order: priority 0 START (first doc arrival, J1: enter Intake, owner via `stage_owner`); 1 FREEZE (`state.fraud.held or flagged`, time = parsed `flagged_at` clamped to at least the watermark and at most `now`); 2 LADDER (next un-emitted 100/150/200 percent crossing of the current stage, none while frozen or terminal); 3 CHASE (fraud-hold copy and escalation); 4 ANSWER (a recorded-but-unprocessed reply, or a persona's due time); 5 EVAL (stage evaluation, scheduled at `max(ready_at, last_arrival + quiet_minutes)`, or at `ready_at` once the stage's gate is satisfied); 5 IMMEDIATE (at `now` only, when unrequested MISMATCH issues exist in the current view).
- EVAL for the current stage S at time t, skipped while frozen or terminal: (1) required facts for S from config (Intake needs legal name and amount): missing means wait. (2) Open issues matching `requestable` that are not in `requested_issues` get one borrower `info_request` at t listing all of them (everything missing at once, J11), then are added to `requested_issues`. (3) Open issues matching S's `blocking` patterns, an OLD_TRICK issue, or a Product vendor check that is explicitly False: wait. (4) If S has a human gate and `gate_sent[S]` is false: build the message, route with `route_gate`, `send_request`, set `gate_sent[S]`, stop; if the gate is not satisfied yet: wait. (5) Exit: write the exit decision and why on S's log entry (`exited_at = t`), enter the next stage (new log entry, `stage_entered_at`, owner, `ready_at = t`, `eval_pending`); the last stage ends the deal (`terminal = closed`).
- Wait means: do nothing, `eval_pending = False`; it re-arms when the view changes, when a stage is entered, or when an answer is processed.
- Transitions are written once per stage. A stage's `StageLogEntry` is created at entry (decision None, why "Entered S: reason") and finished at exit. A held deal's open entry gets decision "held" and a why containing "awaiting Fraud Ops". A declined or stopped deal keeps its open entry with decision and why filled and `exited_at` None.
- Use sorted iteration everywhere; never iterate a bare set.

### D. Routing (routing.py), all from data
- `ids_in(text, teams)`: every known person id appearing in the text, in order of position (ids are preceded by a non-word character and followed by anything except a letter or digit, so a trailing period is fine).
- Out-of-office: regex over `notes` for "OUT OF OFFICE <date> [<HH:MM>] through <date> [<HH:MM>]", case-insensitive, read as -06:00; both edges inclusive; a missing time means 00:00 for the start and 23:59 for the end. `available(pid, teams, now)` walks pid, its backup, their backup (cycle-guarded) and returns the first person not out; if all are out it returns pid.
- `route_detail` returns a `Route(to, primary, covering, until)` and `route_gate` returns `.to`. Resolution by gate: `config.gate_roles[gate]` names an assignment role (credit officer or relationship manager); otherwise the stage that owns the gate: if its stage config has a `routing` object, the delegated or chair person by integer cents (`to_cents(amount) <= to_cents(delegated_max_amount)` means delegated; unknown amount returns None); otherwise the first person id in the gate's `who` text, then in `teams.routing[stage]`; the fraud-hold gate uses the ids in `stages.fraud_hold.who_decides` (first is the analyst, backup from teams, second id as fallback). Unknown gate returns None.
- `stage_owner(stage, state, rules, now)` for ladder recipients: the stage's gate route if it has a gate; else the ids in `teams.routing[stage]`; one id is the owner; two or more mean round-robin (J2): deals are numbered by first-seen order in an ordered list stored on the `rules` object by `object.__setattr__(rules, "_move_intake_order", [])` (Rules is frozen but the list is per-run, so runs stay deterministic) and the pool is indexed modulo its length.
- The RM comes from `assignments.rm(folder)`. People's display names come from `teams.people[id]["name"]`, falling back to the id.

### E. Persona model (inbox.py)
- Persona = `{wall_hours, business_minutes}` or `null` (never answers). Answer time = `business_add(request_time + wall_hours, business_minutes)`. Shipped personas: fast (0, 15), slow (0, 1200), ooo (72, 15), never (null). Lookup order: `by_person[to]`, `by_type[gate]`, `default`; env var `PRISM_MOVE_PERSONA` overrides `default` at config load. The answer option per gate type comes from `responder.answers`. The borrower never answers (documents arrive through arrivals).
- `record_reply(state, rules, idx, option, at)` is the single reply path: reject unknown options (against `gates[type].options`) and requests that are not pending; set `answer` and `answered_at`; close every other request in the same group by setting `answer` to the config's superseded label and `answered_at` to the same time; mark `recorded`. The ANSWER event then applies the stage effect: option in `advance` sets `gate_satisfied`; option in `stop` ends the deal (declined or stopped, log says why); option in `info` (credit request_info) sends a borrower info_request and re-opens the gate after the next arrival and quiet period; any other option is recorded and the deal waits. While a deal is frozen, answers to non-fraud requests are not applied.

### F. Credit memo inputs (credit_memo.py)
Read does not exist yet, so the memo reads facts from `state.facts` (legal_name, amount_requested, product, term_months, purpose_category, annual_revenue_stated, needed_by) and everything else from one optional dict, `state.features["profile"]`, with money as integer cents: dba, ownership, formation_date (ISO), application_date (ISO, default first doc date), preparer, use_of_proceeds, collateral, statement_months, tax_doc ("tax_return" or "form_7004"), net_income_ytd_cents, ytd_months, net_income_fy_cents, deposits_annualized_cents, cash_cents, receivables_cents, liabilities_cents, relationship {status: new, returning_clean or returning_past_due; since_year; prior_loans}, quote {number, vendor, total_cents, remit_last4}, vendor_verified, vendor_past_loans, disbursement {kind: borrower or vendor, bank, last4, vendor, past_loans}, mismatch_evidence {field: {application, document, value}}; plus `state.features["fraud_watch"]` (reason string when the deal is on the watch tier). A missing input prints "not provided"; a test that needs a missing input is scored at its maximum points (conservative) and the memo says so in a confidence line. The memo text never contains a bare brace pair or the word None.

### G. Messages (messages.py)
Plain words, 2-4 sentences, names not ids, borrower = legal name (folder name when unknown) plus DBA plus RM name, times like "Tue 11/03 3:05 PM CT", durations like "26h 10m", money like "$248,000" (cents shown only when not whole dollars), purpose with spaces. Build text by concatenation or f-strings only, never `str.format` on any text derived from a document (legal names can contain braces). Required builders: the three ladder alerts, the waiting-on and unblock rows (missing document, missing page, mismatch, unanswered sign-off, fraud hold pending, vendor not verified, commitment letter), reminder plus backup copy, credit_decision, committee_approval (short memo plus the delegated-limit sentence on the delegated route), commitment_signoff, funding_release, fraud_hold, borrower info_request with the bullet table, deadline-risk. Covering sentence "You are covering for X, who is out of office until DATE." whenever a request is routed to a stand-in.
