<objective>
Build the regression that answers the question "does the engine hold good deals?" on the only labelled population we have: the 257 history deals. Each one is replayed as if it were a brand-new application against the history minus itself, entities and deposit rows injected exactly as Read will leave them. A good deal that comes out held is a false hold. The two ring deals hidden in the history are probed separately, and the M18 history-flag set a ring probe produces is compared with `eval/gold.json`.

Purpose: ROADMAP success criteria 2 and 3 and FRD-07 ("trap suite: zero false holds, zero history false flags"), measurable now, before Read lands. It also gives the freeze gate (05-09) and every plan after this one a single command.
Output: `prism/fraud/trap.py` with a CLI, and tests.
</objective>

  <behavior>
    - `run_trap(history_dir, gold, cfg, *, limit=None) -> dict`:
      - builds `full = build_baseline(history_dir, cfg)` and reads `monthly_deposits.csv` rows per deal with the csv module.
      - for each history deal h in `full.ordered_ids()` (first `limit` when given): `loo = full.restricted_to(all ids except h)` with `loo.calibration = full.calibration`; a `DealState(folder="probe-" + h)` with one `EntityRef(kind, value, "history/" + h)` per entity of h's profile and `features["deposit_months"]` set from h's rows when it has any; stage Intake; `now` = the application date at 12:00 in `SIM_TZ`; `evaluate({folder: state}, loo, cfg, now)`.
      - verdict per deal: `held` (per_deal block held), `watch` (a cluster with tier watch contains the folder), `families` (names fired in its cluster, sorted).
      - groups: `ring` = ids in gold `history_flags`; `fraud_confirmed` = final_status fraud_confirmed; `good` = every other deal (funded clean, unlabelled declined or withdrawn, past due and charged-off funded deals with label none). `false_holds` = sorted ids in `good` that were held. Counts: n_good, n_good_watch, n_fraud_confirmed_held (information only: these are single-deal old tricks the cross-deal logic is not built for).
      - ring probe: for each ring id, whether it is held as a lone current deal, its families, and `history_flags_probe` = `cluster.history_members` over the entity keys of a probe built from the first ring id, against `full` (ring members included), with `cfg.history_min_links`; `must_not_flagged` = intersection with gold `history_must_not_flag`.
      - `pass` is true iff `false_holds` is empty, `set(history_flags_probe) == set(gold history_flags)` and `must_not_flagged` is empty.
    - Report: dict with `meta` (n_history, tau, n_clean, the git-free facts only), `groups`, `false_holds`, `ring`, `history_flags_probe`, `gold_history_flags`, `must_not_flagged`, `pass`. `render_markdown` gives the same in words and tables (counts and ids, no entity values).
    - CLI `python -m prism.fraud.trap [--history DIR] [--gold PATH] [--fraud-config PATH] [--out-dir DIR] [--limit N]`; default history `data/participant/history`, gold `eval/gold.json`, out `out`. Writes `fraud_trap.json` and `fraud_trap.md` (sorted keys, LF, floats rounded to 4 places, no timestamps). Exit codes: 0 pass, 1 fail, 2 usage or missing input (history dir without deals.csv, unreadable gold).

Assert: no filler deal held, no decoy flagged, the probe's `history_flags` equal the planted ring, `pass` true, two runs byte-identical, `--limit` works, exit code 2 on a missing directory.
