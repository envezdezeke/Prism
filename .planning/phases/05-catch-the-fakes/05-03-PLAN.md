<objective>
Make entity matching robust to how a fraudster (or a sloppy scanner) writes the same thing, and stop junk values from creating links. Today a phone with an extension, an account written `xxxx7788`, a preparer written `Zorn, K.` or an address with `#100` all miss; two different addresses (`12 Elm St Ste 100` and `100 Elm St Ste 12`) falsely merge; "N/A", "(owner)" and an unseen bank link unrelated honest deals; and repaid history counts even when it is only `current`.

Purpose: red-team R5 and R7, the matching quality every cluster depends on. A link that should exist but does not is a missed ring; a link that should not exist is a false hold.
Output: per-kind canonical keys, placeholder suppression, outcome-aware rarity weights, errored deals kept in the graph, and a table-driven canon test file.

`eval/synth.py`, `eval/run_synth.py` and the Read step call `canon_value(kind, raw)` and `build_graph` re-canonicalizes everything, so the public function names and signatures in canon.py stay as they are; only behavior improves.
</objective>
