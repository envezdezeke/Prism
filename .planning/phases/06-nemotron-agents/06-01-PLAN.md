<objective>
Pull the shared Nemotron client out of prism/read/vl.py into prism/agents/client.py, following the locked NEM-01 decision. The client covers the off/replay/live modes, the .env loader, the urllib transport, env model IDs, the digest, the record/replay cache and the bounded retry and budget loop. vl.py then uses the client and behaves exactly as before. NEM-05 (the VL reader) shipped in Phase 3 (03-04/03-05). This plan only keeps it working, and the untouched tests/test_read_vl.py proves that. On top of the client, add ChatClient: a tool-calling chat session in the OpenAI chat-completions wire format, with record/replay keyed by hash(model, messages, tools, params) (MODEL_DESIGN N8). The investigator (06-02) and the red-team (06-03) are built on it.

Tool-loop note: the locked wording is "plain OpenAI-SDK tool loop". The `openai` package is not installed. Adding it would need the package-legitimacy checkpoint, and the deadline has no room for that. So ChatClient speaks the same OpenAI chat-completions protocol (`tools`, `tool_choice`, `tool_calls`, `role: tool`) over the existing urllib transport. There is still no agent framework. If the user wants the SDK package itself, that is a one-line transport swap inside post_chat later.

Purpose: one client, one cache format, one place where the key lives. The agents stay off the scored path, and switching Nemotron off provably changes nothing that is scored.
Output: prism/agents/__init__.py, prism/agents/client.py, a slimmer prism/read/vl.py, conftest isolation for agent dirs, tests/test_agents_client.py.

Boundaries: do not edit prism/fraud/** (a concurrent Phase 5 executor owns it), prism/engine/**, prism/move/**, prism/api/**, config/read.yaml, or any vl.py logic outside the env/transport/cache/call section. Do not install packages.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Information disclosure | client.post_chat, NemotronError, cache_write | high | mitigate | The key is read only through env() and placed only in the Authorization header. Error messages are fixed short texts ("http CODE", "timeout"). Cache records hold model and answer only. Test 1 and Test 7 assert a sentinel key never reaches cache files or logs. |
| T-06-02 | Tampering | replay cache files | medium | mitigate | Cache answers feed only advisory agent text or VL fills that still pass vl's format, grounding and cross-document checks (unchanged). Nothing from the cache can create an issue or a hold. |
| T-06-03 | Denial of service | call_with_retries, ChatClient | medium | mitigate | Bounded retries (2) with fixed sleeps, a per-run budget (VL 30 from read.yaml, ChatClient max_calls 40) and a 60 s timeout. A failed key is not re-asked in the same run. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan. The openai SDK is deliberately not added; the transport stays stdlib urllib. |
</threat_model>
