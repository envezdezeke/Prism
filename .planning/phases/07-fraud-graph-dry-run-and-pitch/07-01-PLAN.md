Step 3, pure module ui/src/graph/graphview.ts. It imports only from ../time/timeview.ts with an explicit .ts extension, so node can run it. Define structural interfaces for the node, edge, cluster and graph shapes matching prism/contract.py, and export:
- edgeTimes(graph): the sorted distinct first_visible_at instants in ms.
- arrivalMs(details): a map from folder to the ms of the first stage_log entered_at, skipping deals with an empty log.
- serverViewAt(graph, t): the server's rule, verbatim from prism/api/app.py: edges with first_visible_at at or before t, and entity nodes touched by at least one of them. Deal and history nodes are always kept.
- visibleAt(graph, t, arrivals): D-33. Edges as in serverViewAt; entity and history nodes once they have a visible edge; a current deal node once its arrival is at or before t or it has a visible edge.
- heldIdsAt(details, t): the folders whose heldAt is true at t.
- layoutEvents(graph, arrivals): the sorted distinct union of edgeTimes and arrival instants. These are the layout keyframe times.
- edgeWidth(weight, maxWeight): 0.75 plus 2.25 times weight over maxWeight, and 0.75 when maxWeight is 0.
- edgeAlpha(rarity): 0.15 plus 0.85 times rarity, clamped to 0..1.
Edges are identified by their index in the fetched array, never by a string built from engine text.

Step 4, seeded layout module ui/src/graph/layout.ts, implementing D-34. Import the force functions from d3-force and the helpers from graphview.ts. Export:
- seedPositions(ids): sorts the ids and places them on a sunflower spiral by index (radius proportional to the square root of the index, golden-angle steps). It uses no randomness, so the network starts dispersed in every direction (D-30).
- createLayout(graph, arrivals): returns an object with positionsAt(t), giving a map from node id to x and y.
Keyframes are computed lazily, in time order, and cached by index:
- Keyframe k is at layoutEvents[k] and contains the nodes visibleAt that time.
- A node already present keeps its position from keyframe k-1.
- A new node starts at the mean position of its already-placed linked neighbours, plus a small fixed offset derived from its spiral index. With no placed neighbour, it starts at its seedPositions spot.
- Then a d3-force simulation runs headless: stopped, ticked a fixed number of times (120 for the first keyframe, 60 after), with its random source set to a seeded linear congruential generator and a fixed alpha schedule. Forces are:
  - a link force over the visible edges, with strength 0.05 plus 0.95 times rarity and distance 30 plus 90 times (1 minus rarity), so rare links pull hard and short and common links pull weakly and long;
  - a many-body repulsion of about -60;
  - weak gravity toward the origin on x and y (about 0.03);
  - a collide radius of about 10.
- You may tune these constants (Claude's discretion), but the tests below must hold.
positionsAt(t) returns the keyframe for the last event at or before t. It is empty before the first event. Asking for an earlier time after a later one returns exactly what a fresh layout would return (keyframes are path-independent). If the approved d3-force version has no random-source setting, keep the seeded starts, which leave no two nodes coincident, so the library's random jiggle never runs. The determinism test still decides.
