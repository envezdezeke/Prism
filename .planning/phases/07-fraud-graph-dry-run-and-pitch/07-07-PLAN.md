Write tests/test_seal_blind_run.py first with synthetic names only (the repo's tests never use sample names), watch it fail, then write scripts/seal_blind_run.py. Standard library only. All engine work goes through subprocess calls of the existing CLI with sys.executable and the environment variable PYTHONUTF8 set to 1. It writes only under out/blind_drop/ (or --out-dir) and the two eval/ record files named below, and refuses any output path that resolves inside a folder named data.

Pure functions (tested): aggregate_submission(sub), refusal_reason(record_exists, gold_exists, tree_dirty, tag, tag_commit, head), sha256_file(path), verify_sha(path, expected), aggregate_score(score, sub). None of them returns a folder name, a history id or any extracted value, only counts (D-46).

Command `seal`: arguments --folder, --arrivals, optional --data-root, --out-dir (default out/blind_drop), --record (default eval/blind_drop_record.json), optional --tag. Before any run, compute refusal_reason from: whether the record file exists (a sealed first run is never overwritten), whether eval/gold_drop.json exists (labels must come after the seal), whether `git status --porcelain -- prism config` is non-empty, and whether --tag, when given, resolves to a commit other than HEAD. On a refusal print the reason and exit 2 without running anything. Otherwise run `prism run` twice into run1.json and run2.json, run `prism validate` on run1.json against the folder, and write the record JSON with: the full commit hash, the tag or null, a UTC wall-clock timestamp (not a sim time), deals, errors (parsed from the CLI's run line), held, flagged, history_flags, validator_ok, deterministic (the two files byte-identical), run1_sha256, and the command line without any path inside data. Print the same fields. Never print or write a deal name.

Command `score`: arguments --gold (default eval/gold_drop.json), --out-dir, --record, --score-out (default eval/blind_drop_score.json). It first verifies the SHA-256 of out-dir/run1.json against the record and exits 2 with "output changed since sealing" if they differ. Then it runs `prism score` on run1.json with the gold file into out-dir/score.json (the per-deal detail stays under out/), computes aggregate_score and writes --score-out with record_commit, run1_sha256 and the aggregates. Print the aggregates only.
  </action>
