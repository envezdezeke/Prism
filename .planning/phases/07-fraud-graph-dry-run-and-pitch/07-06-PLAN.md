Write tests/test_synthetic_drop.py first, with synthetic deal names only (no sample name appears in a test; the repo's tests keep that rule), watch it fail, then write scripts/synthetic_drop.py with these importable functions and a command line.

build_drop(rows, drop_at, new_deals, late_papers) returns the new rows and a manifest. It groups rows by the first path component and leaves rows with no folder (root-level files) exactly as they are. Deals are ordered by their earliest arrive_at, ties broken by folder name. The last new_deals deals in that order are the new deals: every one of their files is shifted by one constant so that the earliest of them lands exactly at drop_at, which keeps each deal's internal spacing. From the remaining deals, the late_papers deals with the most files (ties by folder name) each have their single last-arriving file (ties by path) moved to drop_at plus fifteen minutes times its position, starting at one. The output is sorted by arrive_at then path (the engine sorts ties by path). It uses no randomness, no clock and no environment: the same input gives the same bytes. Times are parsed and written in the fixed -06:00 offset at minute resolution, the format of the input. Refuse a drop_at that is not a valid sim time, and refuse new_deals or late_papers that exceed the available deals, with a clear message and a non-zero exit.

build_fuzz(folder_src, folder_dst, rows, drop_at) copies the shared folder to folder_dst (the original is never modified) and returns rows plus four extra rows for the first four deal folders in sorted order, one broken file each, arriving thirty minutes after drop_at: a truncated PDF made from the first 200 bytes of that deal's first PDF (an empty file when it has none), an empty PDF, a CSV of 256 deterministic non-text bytes, and a plain-text file named as a JPG. Refuse any row whose path resolves outside folder_src, and refuse to write when folder_dst or an output path resolves inside a folder named data (T-07-19).

Command line: `--arrivals PATH --out PATH --drop-at TIME [--new-deals 3] [--late-papers 4] [--fuzz-from FOLDER --fuzz-folder-out FOLDER --fuzz-arrivals-out PATH]`. It creates parent directories under out/ for its outputs, writes a manifest next to the main output (counts and moved paths, in out/ only), and prints counts only.

Tests: rows preserved as a multiset of paths; every moved row is later than before; untouched rows identical; root-level row untouched; the earliest new-deal file lands exactly at drop_at and internal gaps are preserved; two builds are byte-identical; the late papers are on deals that were not moved; the invalid time, oversize counts and a path outside the folder fail with a non-zero exit; fuzz files exist with the stated sizes and the source folder's bytes are unchanged.

Then prove the path end to end on the real sample (the tracer's verify): build the drop arrivals, run the CLI on them and validate the result.

Pure functions (tested):
- summarise_score(score): reads the structure `prism score` writes and returns false_flags (the list of deal folders with fraud.flagged got true and want false, plus every history.must_not_flagged id), ring_held and ring_total, history_missed and history_extra counts, and the totals block untouched.

Command line: `[--folder data/participant/shared_folder] [--arrivals data/participant/sim/arrivals.jsonl] [--gold eval/gold.json] [--out-dir out/dry_run] [--drop-at 2026-11-07T10:00-06:00] [--write-record PATH] [--extra NAME FOLDER ARRIVALS GOLD]`, where --extra may repeat and adds another set (for example the real weekend drop once 07-07 has sealed it) judged the same way.

Flow:
1. Record git rev-parse HEAD and the output of `git status --porcelain -- prism config` as the start state. Run the engine's pytest suite once (`-m pytest -q`) and record pass or fail; a failing suite fails the dry run.
2. For each set (sample, drop, fuzz, and each extra): run `prism run` twice to a.json and b.json, require both exit 0, require byte equality of the two files, run `prism validate` against the set's folder and require "valid", run `prism score` with the set's gold file (the sample's labels for the drop and fuzz sets) and apply summarise_score. The drop set uses build_drop with new_deals 3 and late_papers 4; the fuzz set uses build_fuzz on the sample folder, with --data-root pointing at the original sample's parent so rules, contacts and history are found. Fuzz errors recorded for a corrupted file are allowed and reported; a crash, a missing file, an invalid file or a wrong key set is a failure.
3. Print one line per set: `DRY RUN {name}: deals=N errors=E valid=yes|no deterministic=yes|no false_flags=n ring_held=x/y history_missed=a history_extra=b`. A set fails on a non-zero exit, an invalid file, a non-deterministic pair or any false flag. A missed ring deal, a late hold, or a changed move score is reported as a warning line `DRY RUN NOTE ...` and never fails the run (a late arrival can legitimately change timing; the golden labels are not edited to hide it).
4. Record git rev-parse HEAD and the git status for prism and config again; if either differs from the start state, print `DRY RUN FAIL code changed during the run` and exit 1.
5. Print `DRY RUN OK` and exit 0 only when no set failed and the suite passed; otherwise `DRY RUN FAIL` with the first cause and exit 1.
6. With --write-record, write a markdown record whose first line is "Engine commit: " followed by the full 40-character hash from step 1, then a UTC wall-clock date (not a sim time), the commands used, and the per-set lines from step 3, counts only. It never writes a deal folder name, a borrower, business or staff name, or any extracted value.
