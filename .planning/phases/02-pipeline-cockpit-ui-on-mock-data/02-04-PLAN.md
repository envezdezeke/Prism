<objective>
Finish the phase: let the user answer sign-off requests from an inbox, see the alert feed, and see answers reflected on the deal detail. Then close the phase with the full gate (tests, build, lint, audit, smoke) and the end-of-phase human-check against the Playbook checklist. This delivers UI-05 and the alerts part of UI-04, and the visual proof for UI-01.

Purpose: success criterion 4 says the reply goes to the API in the contract shape. The mock does not persist replies (RESEARCH), so an in-memory overlay applied before the status filter is what makes the answered state stick and the count drop. At most one reply per request per session is what keeps a demo from sending duplicates when someone scrubs the clock or double-clicks.

Output: overlay logic with tests, the reply client with a pinned request shape, the inbox and alerts screens with navigation and the rail count, overlay answers on the deal detail, and the phase verification record.

## Decision coverage in this plan
D-01 (states, no invented fields, replies limited to contract shape), D-05 (green only for approved or cleared answers, amber only for escalations), D-11 (rail grows only when screens exist; banking vocabulary), D-12, D-14 and D-17 (names or role labels), D-20 (navy buttons including fraud actions, neutral errors, inline confirmations, no toasts), D-21 (inbox replies kept in a client overlay because the mock does not persist them). D-13, D-15, D-16, D-18 carry over from plans 02 and 03.

## Flagged assumptions (spec-less edge fallback)
- UI-05 (concurrency, resolved as a truth above): one reply per request per session through an in-flight guard plus the overlay; a 409 is shown, not retried.
- The overlay's answered time is the UI clock at reply time, not the API's echoed time (the mock echoes a fixed fixture time); the live engine will persist replies in Phase 7 and the overlay then remains harmless.
- The primary option is the first entry of the item's options array; the API sends no priority field.
- "Second escalation" is shown only when the alert message itself says so (the contract has one escalation level).
- Playbook items not built (stretch only, not required): see Optional stretch below.
