<objective>
Stand up the cockpit project and prove the whole architecture on one real path before anything is built out: browser, Vite proxy, mock API, the client-held sim clock, the tested time-derivation module, and a pipeline board rendered from derived data in the Institutional tokens. This is the tracer slice for Phase 2. Everything after it (plans 02 to 04) expands a path that already works end to end.

Purpose: the mock API is stateless and its list endpoints ignore the clock (RESEARCH), so the design only works if the clock lives in the browser and every time-dependent view is derived from timestamps. Proving that on the live mock now, on the best early context, catches a dead end after one commit instead of after four plans.

Output: a building, linted, tested `ui/` app that shows the board at the clock's time, plus a repeatable `npm --prefix ui run smoke` check that Phase 7 reuses when the API flips from mock to live.

The npm-install gate (Task 1) comes first by rule: legitimacy checkpoints must precede any install. Task 2 is the tracer; its scaffold output is generated by verified commands, so the hand-authored surface is small and each file is thin.

## Decision coverage in this plan
D-01 (faithful values, loading and error states on the board path), D-02 (no router, no extra state libraries), D-03 to D-08 (tokens), D-13 (fixed -06:00 formatting), D-18 (derivation owns time), D-19 (bundled Source Serif 4 and Geist), D-20 (neutral errors, no toasts), D-21 (clock held in client state, loaded once). Remaining decisions are covered in plans 02 to 04.

## Flagged assumptions (spec-less edge fallback, unresolved or unclassified rows)
- UI-01 (unclassified): "design system" is taken to mean the Playbook section 2 tokens plus one type scale, tabular numerals and red reserved for holds. Plan 02 adds the Playbook-listed primitives; plan 04 adds an automated audit and the visual human-check.
- UI-02 (unclassified): the board renders however many deals the API returns (never a hard-coded 5 or 13) and shows a deal only once its first stage_log entry has started.
- The Playbook's Geist tabular-figure support is unverified (RESEARCH A1); the end-of-phase human-check confirms digit alignment by eye.
