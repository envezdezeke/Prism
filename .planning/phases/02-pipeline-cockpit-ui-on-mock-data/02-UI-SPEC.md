## Screens and Layout

### App frame

- **Top bar** (56px, white, bottom hairline). Holds only the sim clock. Left: "Sim time (CT)" in caption, then the current time in Dense weight 600 with tabular numerals, for example `Wed 11/04 6:00 PM CT`. Right, in order: `+1h`, `+6h`, `+1 day`, `Next event`, `Pause` or `Play`, `Replay from start`, a "Go to" `datetime-local` input (step 60 seconds), and `Go`.
- **Left rail** (200px, white, right hairline). Three items, 36px each: `Pipeline`, `Inbox` with a count of pending requests at the clock time (neutral, ink-2, tabular), and `Alerts`. The active item shows navy text at weight 600 and a 2px navy bar on its left edge. No wordmark: the product name is unresolved (CLAUDE.md says DealPilot; ROADMAP says Prism).
- **Content**: 24px padding. Page title in Display style (28px serif). Nothing else above the content.
- **Routes** use the URL hash, with no router library: `#/pipeline` (default; unknown hashes also go here), `#/inbox`, `#/alerts`, `#/deals/{encodeURIComponent(folder)}`. Browser Back works. The document title is the current page name.
- **Width**: the minimum supported width is 1280px. Desktop only, no mobile layout. At 1280px the board fits without scrolling: 200 + 48 + (6 × 160) + (5 × 8) = 1248px.

### Clock behavior (UI-03, D-21)

- On load, `GET /api/clock` runs once and sets `now`, `start` and `end`. The clock is never polled, never refetched and never a query. Window focus does not refetch it.
- Every control works on the client `now`, clamped to `[start, end]`.
- `+1h`, `+6h`, `+1 day` add the duration and clamp. Disabled at `end`.
- `Next event` jumps to the earliest event after `now` (see Time View Rules). When none exists, it is disabled with the inline text "No later event".
- `Go to` takes wall-clock Central time with no timezone conversion. It is submitted with `-06:00` appended. `min` is `start` and `max` is `end`. An out-of-range or empty value shows the inline neutral message "Enter a time between {start} and {end}."
- `Replay from start` sets `now` to `start` and starts playback.
- Playback advances 1 sim hour per real second. It pauses at `end`. `Pause` and `Play` toggle it. Playback ticks are client-only and do not call the server.
- Each user-initiated change (not playback ticks) sends `POST /api/clock/advance` with `{"to": "<target>-06:00"}`, never `hours`, or `POST /api/clock/replay`. The response is not used for the displayed time. If the request fails, show the neutral inline message "The clock could not be set on the server. The screen shows {local time}."
- Disabled controls use ink-2 text on a line border with the default cursor. No opacity tricks.

### Pipeline board (UI-02)

- Six columns in contract order: Intake, Credit, Committee, Product, Committed, Closed. Each column is a minimum of 160px, with 8px gaps. Column background is page color. Cards are white.
- **Column header**: stage name (Label), a count (Caption, tabular), and the limit (for example `48h`) only when every deal in that column shares the same `sla_hours`.
- **Card**. The whole card is one link to its deal. Rows, top to bottom:
  1. Legal name (Dense, weight 600, two lines at most, then ellipsis) on the left. Amount on the right: `amount_requested` as money, or `—` when null.
  2. Folder name (Caption, ink-2, one line, ellipsis).
  3. Time in stage and SLA: `26h 10m / 48h · 55%` (Caption, tabular).
  4. SLA bar: 2px, full card width. Track is `#E7E5E4`. Fill is `#78716C` from 0 to 100%. Fill above 100% is amber. The scale runs 0 to 200%. Tick marks (1px `#78716C`) sit at 100%, 150% and 200%. A value above 200% fills to the end, and the text shows the true figure.
  5. Status slot, one badge at most: `Held: fraud review` (red, Held variant) takes priority over `Watch` (neutral outline). A Closed-stage card shows `Cleared` (green) when no hold applies. Otherwise nothing.
  6. Needed-by element, when `needed_by` is present: `Needed by Fri 11/06 3:00 PM CT` in ink-2. When `needed_by_badge` is `at_risk`, the text is `At risk: needed by ...` in amber. When `overdue`, it is `Overdue: needed by ...` in amber. When `none` but a date exists, it is neutral.
- **Card sort within a column**: held first; then needed-by ascending, with no date last; then time in stage, longest first.
- Held cards and Watch cards carry no extra color. The badge is the only signal.
- A card's identity is the legal name with the folder name beneath it (D-15). No DBA is shown, because the contract has no DBA field.

### Deal detail (UI-04)

- **Header**: a breadcrumb `Pipeline / {legal name}` in Caption (the word Pipeline is a navy link). Title in Display style: legal name, or the folder name when the legal name is null. Beneath it, the folder name in Dense ink-2. Then the stage chip and the status slot, as on the card.
- **Main column** (flexible; 688px at 1280px), sections in this order, each with a Heading and 32px between sections:
  1. **Facts.** Table: Field, Value, Source, Confidence. Rows in contract order: Legal name, EIN, Amount requested, Purpose, Product, Term, Guarantor, Annual revenue (stated), Needed by. Money is right-aligned. Term reads `60 months`. Purpose shows its label. Needed by shows sim time. The source is a chip whose text is the `source_doc` value verbatim. Confidence is a whole percent. A null fact shows `—` in tertiary with the tooltip "Not found in documents" in each cell it affects. The heading row carries the Caption "As of end of run" (D-18).
  2. **Issues.** Open issues, one row each: the plain-words label (Dense) followed by the raw code in ink-2 (Caption), separated by a middle dot. No color. A "Resolved" subheading (Label) lists `resolved_issues` in the same format, in ink-2. Caption "As of end of run" on the heading.
  3. **Stage log.** Vertical timeline, one entry per `stage_log` row, filtered by the time rules. Each entry: stage name (Heading), "Current" (Caption) on the open entry, the Entered and Exited times (or "Open for {duration}"), `Decision:` with the value in sentence case or `—` when null, and `Why:` with the full text. No truncation.
  4. **Human requests.** Table: Sent, Type, To, Message (wraps), Answer. Answer reads `Pending`, or the answer label with its time. The inbox overlay applies here too.
  5. **Alerts.** Oldest first. Each row: time, level label, recipient role, full message.
- **Side column** (320px, sticky at the top):
  - Summary panel (6px radius, 1px line, 16px padding). Label/value rows: Stage; Stage entered; Time in stage; SLA; Needed by (value and badge text); Amount requested; Relationship manager (role label, tooltip with the raw id).
  - Fraud panel (same style). Held at the clock time: `Held: fraud review` (red badge) and "Frozen at {stage at flag} as of {flagged time}". Then the plain-words reason in Body, then "Linked" with each `linked_deals` entry. An entry that matches a folder on the board is a navy link. Any other entry, such as a history id, is plain text. Watch: neutral `Watch` badge and "Shown for review. Not held." Flagged but not held: neutral "Flagged, not held." Neither: "No hold or watch flag." The fraud panel has no F1 to F6 checklist (Phase 7).

### Inbox (UI-05)

- **Header**: Display title `Inbox`. Beneath it, a segmented control with two buttons: `Pending {n}` and `Answered {n}`. The active button has navy text and a 2px navy underline.
- **List** (left, flexible), a table with columns Age, Deal, Request, To, Message. Age is the clock time minus the request's `at`, in duration format. Deal is the legal name (Dense, 600) with the folder beneath (Caption). Request is the type label. To is the role label, with the raw id in a tooltip. Message is one line with ellipsis. Pending items sort oldest first. Answered items sort by answer time, newest first. A row is selected by click or by Enter and Space; the selected row shows a 2px navy bar on its left edge.
- **Pane** (right, 320px, 6px radius, 1px line, 16px padding) for the selected item:
  - Legal name (Dense, 600), folder (Caption), request label (Heading), `Sent {time}`, `To {role}` with a tooltip.
  - Full message in Body.
  - Answer buttons: exactly the item's `options`, in order. The first option is a navy filled button. Each other option is a navy outline button.
  - Optional note: an `input` with `maxlength` 500.
  - Status line: `Answered: {option label} · {time}` once answered. Approve answers also show the green "Approved" badge.
- **Answer flow**:
  1. Clicking an option sends `POST /api/inbox/{id}/reply` with `{"option": "<option>"}`, adding `"note"` only when the trimmed note is non-empty.
  2. `decline` and `release_hold` require an inline confirmation first (see Copywriting). `confirm_hold` and the other options submit directly.
  3. While the request is in flight, the buttons are disabled.
  4. On success, the overlay records `{answer, note, answered_at: clock now}`. The status line gets `role="status"` and reads "Answered: ...". The item moves to the Answered list.
  5. On 409, the message is "This request was already answered. The list has been refreshed." The inbox list refetches. This refetch does not touch the clock.
  6. On 422, the message is "The server rejected that option: {detail}".
  7. On a network failure, the neutral error appears with Retry.
- Answers take effect at the clock time they were given. If the clock is scrubbed back earlier, the item shows as pending again and can be answered again. Answers live in memory only, so a reload restores pending in mock mode (documented mock behavior).

### Alerts feed

- Display title `Alerts`. Table: Time, Level, Deal, Stage, To, Message. Newest first. Only alerts with `at` at or before the clock time are shown.
- Level: `Alert` for level `alert`. `Escalation` for level `escalation`. `Second escalation` when the message begins with "Second escalation:" (the MESSAGE_TEMPLATES 200% wording). If NEM-06 later rewrites that prefix, the label falls back to `Escalation`, which is still true.
- Escalation rows (both kinds) carry a 2px amber left border, since they mark SLA past 150%. Alert rows have no border.
- Deal is a navy link to its detail page. To is the role label: "Stage owner" for `alert`, "Escalation contact" for `escalation`, with the raw id in a tooltip.

## Time View Rules (D-18)

All time-dependent values come from one pure module, `viewAt(now, data)`. Screens never read raw fixture times directly.

1. **Arrival.** A deal is visible only when its first `stage_log` entry has `entered_at` at or before `now`.
2. **Current stage.** The last `stage_log` entry with `entered_at` at or before `now`. A held deal keeps its last stage (Intake), since held deals have no open entry.
3. **Time in stage.** From the current entry's `entered_at` to an end point. The end point is the earliest of: `now`; `fraud.flagged_at`, only when the deal is held and that time is at or before `now`; and the current entry's `exited_at`, only when that time is at or before `now`.
4. **SLA fraction.** Time in stage divided by `sla_hours`. Displayed as `round(fraction × 100)%`. Amber when the displayed value is above 100%. The rule freezes a held deal's SLA at `flagged_at` (for example, Bayou Bistro & Grill at 44%).
5. **Held at `now`.** `fraud.held` is true and `flagged_at` is at or before `now`. The reason, stage at flag and linked deals appear only when held at `now`. Watch has no timestamp, so it is shown as given (end of run).
6. **Stage log rows.** Shown when `entered_at` is at or before `now`. `exited_at` is shown only when it is at or before `now`. Otherwise the row reads "Open for {duration to now}".
7. **Human requests.** Shown when `at` is at or before `now`. The answer is shown only when `answered_at` is at or before `now`, from the server value or from the overlay. The overlay joins to a request on (deal, type, at).
8. **Inbox.** Pending at `now` when `at` is at or before `now` and no answer applies at `now`. Answered at `now` when an answer (server or overlay) has `answered_at` at or before `now`.
9. **Alerts.** Shown when `at` is at or before `now`. The board feed is newest first; the detail list is oldest first.
10. **No timestamp.** Facts, issues, resolved issues, `needed_by`, `amount_requested`, `rm`, `watch` and `needed_by_badge` are shown as the server gives them (end of run). Each such section carries the caption "As of end of run" (D-18).
11. **Next event.** The minimum of every timestamp after `now` among: stage log `entered_at` and `exited_at`; `fraud.flagged_at`; human request `at` and `answered_at`; alert `at`; and overlay `answered_at`. Across all deals.
12. **Overlay.** The in-session answer applies on top of fetched inbox items and detail requests.
13. **Bad value.** A time that does not match the `-06:00` format is displayed as its raw string. It never blanks a screen.

## Interaction and State Contract (D-01)

Every data view has loading, empty and error states.

| View | Loading | Empty | Error |
|------|---------|-------|-------|
| Clock (top bar) | "Loading clock." in the top bar; page waits | Not applicable | Page-level neutral error with Retry; no screen renders without a clock |
| Board | "Loading deals." | Zero arrived: "No deals have arrived yet." Per column: "No deals in {Stage} as of {time}." | "Could not load deals." with Retry |
| Board, partial | Cards for loaded deals render as their details arrive | Not applicable | A line above the board: "{n} deals could not be loaded. Retry." Those deals are omitted, since their stage cannot be placed without the stage log |
| Deal detail | "Loading deal." | Facts all null: "No facts were extracted for this deal." No open issues: "No open issues." No resolved issues: "No resolved issues." No requests: "No requests on this deal as of {time}." No alerts: "No alerts on this deal as of {time}." | Deal not arrived at `now`: "{legal name} has not arrived as of {time}." with "Back to pipeline". 404: "This deal is not in the run." Other: describeError with Retry |
| Inbox | "Loading requests." | Pending: "No pending requests." with body "Everything is waiting on borrowers or the clock." Answered: "No answered requests as of {time}." | describeError with Retry. 409 and 422 use the messages in the answer flow |
| Alerts | "Loading alerts." | "No alerts yet." with body "Alerts fire at 100% of a stage's limit and escalate at 150% and 200%. None had fired as of {time}." | describeError with Retry |

describeError mapping:
- 503 gives "The engine is not connected."
- A network failure gives "The API is not reachable. Start the mock server on port 8000."
- 404 for a deal gives "This deal is not in the run."
- Any other error shows the server's `detail` string, as text.
- Otherwise: "Request failed (HTTP {n})".

Server strings are untrusted data. They render as React text, never as HTML.

Overflow and long text:
- Legal names clamp to two lines on cards, then ellipsis. In table cells they are one line with ellipsis.
- Inbox messages wrap in the pane and clamp to one line in the table.
- Stage log "why" text and the fraud reason wrap in full. They are never truncated in the detail view.
- Board columns scroll vertically inside their scroll area.

Keyboard and focus:
- Tab order: rail, top bar controls, then page content in reading order. Board cards are links in column order. Inbox rows are selectable buttons.
- Focus is a 2px navy outline with 2px offset, on every interactive element. Never removed.
- No modal dialogs. Confirmations are inline. Escape closes tooltips.
- Text contrast is at least 4.5:1 everywhere. Color is never the only signal: every badge carries its words.

Motion: none. Color changes on hover and focus are allowed at 150ms. `prefers-reduced-motion` is respected. Playback updates are instant, not animated.

## Implementation Rules (for the executor)

- Colors, sizes, radii and spacing come only from the tokens in `ui/src/index.css`. No raw hex or pixel size in components. Only the token utilities are used in components.
- Time logic lives in one pure, tested module. Screens consume only its output. Test with `node --test`.
- Never hard-code the sample count. The fixture has five deals; the real sample has thirteen. Columns and lists derive from the data.
- Encode every folder name in a path with `encodeURIComponent`. Folder names contain apostrophes, ampersands and spaces.
- Render all engine and document strings as text. No `dangerouslySetInnerHTML`. No `href` built from engine strings, except same-app hash routes built from encoded folder names.
- No participant data in `ui/`: no `data/`, no `teams.json`, no PDFs, no staff names. `dist/` is not committed.
- Clock: `GET /api/clock` once. No polling. No refetch on focus. `POST` only for user-initiated changes, using `to`, never `hours`.
- Inbox answers are an in-memory overlay. Never write a response into the query cache.
- Do not install a router, toast, theme, chart or animation library (D-02; D-20).
- Fixture quirks are displayed as given and flagged to Zeke, never corrected in the UI: `inbox-002` routes a $410,000 committee approval to `committee.osei`; `inbox-003` and `inbox-004` route fraud holds to `fraudops.keller`; `rm` values are ids that are not in the directory.
